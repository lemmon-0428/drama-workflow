# Drama Script Split（剧本拆解）

把一份整本/多集合一的剧本，**保真**切成单集文件，作为后续 `drama-bible`（设定）、`drama-storyboard`（分镜头）、`drama-asset-gen`（资产）的输入。职责是"切分 + 不丢内容"，不是改写或总结。完整流水线契约见 `docs/流水线设计.md`。

## 输入

- 剧本文件：`.docx` / `.pdf` / `.txt` / `.md`（旧 `.doc` 先让用户另存为 `.docx`）
- 或已抽取的纯文本
- 剧名（决定输出目录 `docs/scripts/<剧名>/`）；用户没给就从 `《…》` 标题或文件名推断并说明

## 第一步：先 dry-run 看结构，别急着写

拆错边界比不拆更糟。先用脚本的 `--dry-run` 看它检测到的分集结构，确认无误（或发现需要人工干预的地方）再正式拆：

```bash
python .claude/skills/drama-script-split/scripts/split_script.py --src <剧本文件> --drama <剧名> --dry-run
```

脚本会识别：标题/副标题、`【故事梗概】`、`【剧本正文】`+风格设定、分集/分幕标记（`第N集`/`第N幕`/`终幕`/`ACT`/`EP`/`FINALE`，含**无显式首集/首幕的开篇段落**）、每段时间码。重点核对：
- 集数对不对？有没有把一集错切成两段、或两集并成一段？
- 第一幕/开篇是否被正确识别（很多剧本首幕无显式标记）？
- "正文合计 + front matter = 非空总计"是否吻合（脚本会打印），**不吻合说明有内容被漏掉**。

结构没问题就去掉 `--dry-run` 正式拆分。结构异常（罕见格式/标记混乱）时，读原文人工确定边界，必要时手写拆分而不是硬套脚本。

## 输出

```
docs/scripts/<剧名>/
├── 00_剧集总览.txt              梗概 + 创作设定 + 分集目录
└── 第N集_<短标题>/
    └── <剧名>_第N集_<短标题>.txt
```

每个单集文件结构：头部（集号·短标题 / 原始结构 / 时间码 / 全剧通用创作设定）+ `正文`。

## 保真规则

- **保留原文**：场景标注、对白、人物名、舞台说明、中英对照，全部原样保留，不总结、不润色、不增删情节。
- 单集文件正文里**不要**塞拆分依据/置信度/元信息这类东西——那些写进总览或单独说明。
- 首幕无显式标记时，按"开篇段落"处理并在文件头标注"时间码为推断"。
- 完全没有任何分集标记 → 整本作为"第1集_全"，并说明这是单集判断。

## 质量自检

- `00_剧集总览.txt` 存在，分集目录齐全。
- 每集一个目录 + 一个 `.txt`，命名 `第N集_<短标题>`。
- 脚本打印的"正文合计 + front matter = 非空总计"吻合，无内容丢失。
- 集号连续（除非原文本身跳号）。
- 最后向用户报告：拆了几集、路径、以及任何不确定的边界 / 抽取质量问题。

# 短剧 AI 视频生产流水线 · 完整文档

> 从一本剧本到成片视频的 **5 段式**流水线，**0 抽卡**（每段的主体/场景/构图靠 ref 锁定一致性）。
> 本版参考专业作品「万物生」工作流重构：资产升级为**多面板角色参考表**，分镜升级为**手绘草图分镜板（一段一张，显式画机位/硬切/轴线）**，视频单元从"一组"变为**一段 segment**。
> 本文以 **步步生金 · 第 1 集《绝望降临》** 为例，讲清每个 skill 的职能、输入输出、产物文件与目录结构。
>
> skill 之间**没有共享记忆，只有共享文件系统**：每个 skill 读上一环节写的文件、写自己的文件。**目录结构 = skill 之间的 API**；**一套统一 ID（`ref_token`）把各环节串起来**。

## 一、全流程总览图

```
 整本剧本(docx/pdf/txt)
        │
        ▼
┌─────────────────┐  ① drama-script-split   拆解
│  把整本剧本保真切成单集 + 剧集总览                        │
└─────────────────┘
        │  产: 00_剧集总览.txt、第N集_*/<剧名>_第N集_*.txt
        ▼
┌─────────────────┐  ② drama-bible          设定 Bible
│  通读全剧 → 人物富 sheet_spec + 同阵营 factions[] + 全剧 STYLE LOCK │
└─────────────────┘
        │  产: bible/{世界观,人物背景,场景设定}.md、bible.json(assets[] status:planned)
        ▼
┌─────────────────┐  ③ drama-asset-gen      资产生成 ★前移到分镜之前
│  按 bible 出三类库资产: 多面板角色参考表/场景板/道具图        │
└─────────────────┘
        │  产: assets/{characters,scenes,props}/*.png、asset_registry.json、角色形象卡.md
        ▼
┌─────────────────┐  ④ drama-segment        分段 + 蓝图
│  单集 → segment(连续戏剧节拍,含段内硬切,由草图板引导)        │
│  每段产: 色卡 / staging / 草图分镜板 / 段prose / 资产绑定     │
└─────────────────┘
        │  产: 第N集/分段/{分段计划.md, scenes/*.png, 段提示词.md,
        │                  资产绑定.json, 资产锚定方案.md, asset_registry.json}
        ▼
┌─────────────────┐  ⑤ drama-sd2-request    SD2 出片
│  每段=一次 Seedance: text=段prose + 四件套 reference_image      │
│  @token→path→OSS→moyu素材库 asset://id → Seedance 2.0 生成     │
└─────────────────┘
        │  产: 第N集/sd2/{sd2请求,moyu_payload,提交记录}.json、sd2/videos/*.mp4
        ▼
   成片 mp4(本地)
```

**关键重排（相对旧 6 段式）**：③ 资产**前移到分镜之前**（草图板要画已生成的角色参考表，保长相一致）；旧「③分镜头 + ④镜头提示词」**合并为 ④分段+蓝图**；术语映射："镜"→草图板里的"格"，"组"→segment。

**数据主线**：同一个"请求"沿途被逐步具化——
`剧本文字 →(②)bible 设计意图 →(③)token→库资产图 →(④)分段+四件套蓝图 + @token→path 绑定 →(⑤)reference_image + moyu素材id → 视频`。

```
├── 第1集_绝望降临/                     ← 单集工作目录(本文示例)
│   ├── 步步生金_第1集_绝望降临.txt      ① 单集剧本(保真切分)
│   ├── 资产清单.md                      ③ 人读: 本集复用 vs 新增资产
│   ├── 分段/                            ④ 分段 + 蓝图
│   │   ├── 分段计划.md                  4a 全集切段(每段镜序/硬切/whip pan/180°轴/站位/分量)
│   │   ├── scenes/                      4b 蓝图图: 色卡_<场景>.png · staging_<段>.png · SEG-*_草图板.png
│   │   ├── 段提示词.md                  4c 每段 prose(万物生级) + 每段有序锚定清单
│   │   ├── 资产绑定.json                4d 每段 ref_set(@token→path) + duration/ratio (⑤ 的输入)

│   │   └── asset_registry.json          本集蓝图(色卡/staging/板)生成日志
│   └── sd2/
│       ├── sd2请求.json                ⑤ 每段中间请求(ref_set 解析 + payload)
│       ├── moyu_payload.json           ⑤ moyu 原生请求体(metadata.content: text + image_url asset://id)
│       ├── 提交记录.json                ⑤ task 台账(task_id/query_url/状态/本地视频)
│       └── videos/*.mp4                 ⑤ 成片(自动下载, 段_段名.mp4)
│
├── 第2集_城市谋生/  第3集_全网爆红/  第4集_衣锦还乡/    (只到 ① 剧本,后续按需推进)
```

**剧集级 vs 单集级**：`bible/` 和 `assets/` 是**全剧共用**（人物表、场景板、道具图跨集复用）；其余按集分目录。

## 三、统一 ID 约定（ref_token）

| 类型 | token | 指向 | 谁产 |
|---|---|---|---|
| 人物 | `@[char:<id>\|look:<look>]` | 多面板角色参考表 | ②规划 → ③出图 |
| 场景 | `@[scene:<id>\|look:<look>]` | 场景板 | ②规划 → ③出图 |
| 道具 | `@[prop:<id>]` | 道具图 | ②规划 → ③出图 |
| **色卡** | `@[palette:<id>]` | 13 色色卡（按场景/段复用） | ④产 |
| **草图板** | `@[board:<seg_id>]` | 草图分镜板（每段一张） | ④产 |

- **id**：英文小写下划线，全剧稳定。`look`：造型/状态/打光变体短标签。
- **资产文件名**：base=`<id>.png`；变体=`<id>__<look>.png`。色卡/草图板存 `分段/scenes/`。
- **段 id**：`ep<N>_<段序>`（如 `ep1_1A`）；segment 显示名 `SEG-1A`。
- **衔接链**：② 定 char/scene/prop 的 token+sheet_spec → ③ 按 token 出库资产 → ④ 切段、产 palette/board 两类新资产、每段定**有序锚定清单（ref_set）**写 `资产绑定.json` → ⑤ 按 ref_set 取 path 拼 reference_image。

## 四、逐 Skill 详解

### ① drama-script-split（剧本拆解）
| 项 | 内容 |
|---|---|
| **职能** | 把整本/多集合一的剧本**保真**切成单集文件，建目录与总览。只切分、不改写。 |
| **输入** | 整本剧本 `.docx/.pdf/.txt/.md` + 剧名 |
| **输出** | `00_剧集总览.txt`、`第N集_<短标题>/<剧名>_第N集_<短标题>.txt` |
| **关键工作** | `split_script.py --dry-run` 先验分集边界（标题/梗概/分集标记/时间码）→ 核对集数无误 → 正式拆；保证"正文+front matter = 总计"不丢内容，中英对照保留 |

### ② drama-bible（设定 Bible）
| 项 | 内容 |
|---|---|
| **职能** | 通读全剧，产"设计意图层"。叙事写 `.md`，视觉锁定写 `bible.json`。只定"应该长什么样"，真资产由 ③ 生成。是全剧设计唯一事实来源（SoT）的**规划层**。 |
| **输入** | 全剧所有单集 txt（必须通读全剧，look 计划是跨集的） |
| **输出** | `bible/{世界观,人物背景,场景设定}.md` + `bible/bible.json` |
| **关键工作** | 每角色写富 `sheet_spec`（多面板参考表结构化字段：族群/骨相/服装/signature/武器/打光/反例…）+ 造型 + look 规划（parent/planned_episodes）；同阵营写顶层 `factions[]` 差异化表（同模板+同 lighting，靠差异表保家族一致又可区分）；全剧 `style_lock`。`assets[]` 全 `status:planned`（出图态归 ③ 的 registry） |
| **数据契约** | `bible.json` 严格按 `docs/asset-schema.md`：`drama/style_lock/factions[]/assets[{ref_token,category,id,look,status,intent{sheet_spec\|spec_prompt,planned_episodes}}]` |

### ③ drama-asset-gen（资产生成 · ★前移到分镜之前）
| 项 | 内容 |
|---|---|
| **职能** | 按 bible 多渠道出三类**库资产**（跨集复用），并追踪台账。**不再产站位图、不再产资产绑定**（已移交 ④）。 |
| **输入** | `bible.json`（按 `planned_episodes` 含本集的资产算需求） + `asset_registry.json`（已有） |
| **输出** | `assets/{characters,scenes,props}/*.png`、`asset_registry.json`、`assets/角色形象卡.md`、`第N集/资产清单.md` |
| **三类库资产** | ① **多面板角色参考表**（4 格：正脸/侧脸/无脸全身/背面，9:16，按 bible `sheet_spec` 填 character-sheet-template；同阵营靠同模板+同 lighting+`factions[]` 差异化，视觉相近阵营叠编辑模式）；② **场景板**（16:9）；③ **道具图**（1:1，含需中文 HUD 等特殊项） |
| **关键工作** | 去重分类（复用/新 base/变体）；多渠道生成 micu→packy→moyu 回退；画幅 character 9:16 / scene 16:9 / prop 1:1；台账记 path/size（实际画幅）/provider/used_by（跨集复用追踪）；设计全部取自 bible，本环节不重新设计 |

### ④ drama-segment（分段 + 蓝图）
| 项 | 内容 |
|---|---|
| **职能** | 一手包办分镜调度 + 渲染规格。把单集切成 **segment（连续戏剧节拍，3-4 镜、~12s，含段内硬切，由草图板引导）**，并为每段产四件视觉蓝图 + 锚定。 |
| **输入** | 单集剧本 + `bible.json` + 已生成的 `assets/`（角色表/场景/道具） |
| **输出** | `第N集/分段/{分段计划.md, scenes/*.png, 段提示词.md, 资产绑定.json, 资产锚定方案.md, asset_registry.json}` |
| **4a 切段** | 用三层技法库（`vol1-类型场景`/`vol2-对话功能`/`vol3-技术工具`）严格选库；每段定镜序/硬切/whip pan/180°轴/站位/分量 → `分段计划.md` |
| **4b 蓝图图** | 每段产 ① **色卡**（13 色 HEX，按场景复用，`@[palette:]`）② **俯视 staging 图**（仅多人复杂调度段）③ **手绘草图分镜板**（白纸，N 格=段内镜数+Shooting Plan，显式画机位/硬切/whip pan/180°轴，`@[board:]`）；三套模板见 references |
| **4c 段 prose** | 每段一段（`段提示词.md`，万物生 craft 级）：五块结构（风格锁定/资产锚定/本段执行/声音设计/关键约束）；**构图交给草图板、prose 重心在渲染/表演/声音**；台词用剧本原文中文一字不改、术语留英文 |
| **4d 锚定** | 色卡 `@[palette:]` / 草图板 `@[board:]` 注册 ref_token；每段定**有序锚定清单 ref_set**（`@[board:]` 永远第 1）→ 写 `资产绑定.json` |
| **铁律** | 一段 = 一张草图板 = 一次视频生成；草图板用纯白纸（只承担构图引导，配色只由色卡决定，避免偏色污染） |

### ⑤ drama-sd2-request（SD2 出片）
| 项 | 内容 |
|---|---|
| **职能** | 把绑定翻成 **moyu Seedance 2.0** 请求，直连 moyu 生成视频并下载。**一段 = 一次 Seedance 生成 = 一条请求**。 |
| **输入** | `第N集/分段/资产绑定.json` + 各蓝图图 + 段 prose |
| **输出** | `第N集/sd2/{sd2请求,moyu_payload,提交记录}.json`、`sd2/videos/*.mp4` |
| **每段两件事** | ① `text` = 该段 prose 全文（取自 `段提示词.md`）；② `reference_images` = 该段 `ref_set` **按序**解析（`@[board:]` 草图板永远第 1 = 构图主引导，再 char 人物表 / palette 色卡 / scene 场景 / prop 道具） |
| **关键工作** | 每个 `@token` → `资产绑定.json` 的 `assets{}` 查 path → OSS 上传得签名 URL → moyu CreateAsset → `asset://<id>`（跨集同图复用一个 id）→ 填 `metadata.content` 的 image_url；**全走 reference_image，不用 moyu 互斥的 first_frame，首帧意图写在 prose 里**；task_id 立刻落盘，成功自动下载 mp4 |
| **默认** | 只产请求/预览；真正提交 moyu（`--submit`）是单独动作、需用户确认 |

## 六、第 1 集实例 · 完整走一遍

**剧情**：苏小七一家深陷贫困，主角获"进步系统"，从乡间石板路一路逆袭到城市。

| 步 | 产出 |
|---|---|
| ① | （剧本已拆）`第1集_绝望降临/步步生金_第1集_绝望降临.txt` |
| ② | `bible/bible.json` 等；第 1 集涉及资产：苏小七/苏父/苏母/李叔 + 7 场景板 + 4 道具（含中文 HUD「进步系统面板」） |
| ③ | `assets/` 出 4 张多面板角色参考表 + 7 张场景板 + 4 张道具图 + `资产清单.md` |
| ④ | `分段/` 切 **10 段（SEG-1A…3E）**；每段四件套：`分段计划.md` + `scenes/`（10 张草图板 + 7 张色卡）+ `段提示词.md` + `资产绑定.json` + `资产锚定方案.md` |
| ⑤ | `sd2/sd2请求.json`（每段 prose + 有序四件套 reference）→ 提交得成片 mp4 |

**某段 `资产绑定.json` 的 `ref_set` 顺序长这样**（SEG-1A，节选）——`@[board:]` 永远第 1：
```jsonc
"ref_set": [
  { "token": "@[board:ep1_1A]",      "role": "构图主引导" },   // 图片1 草图分镜板
  { "token": "@[char:su_xiaoqi|look:default]", "role": "主体" }, // 图片2 苏小七参考表
  { "token": "@[palette:ep1_s1_dusk]", "role": "配色" },        // 图片3 色卡
  { "token": "@[scene:rural_stone_path|look:dusk]", "role": "环境" } // 图片4 场景板
]
```
> **顺序铁律**：`ref_set` 是有序 list，⑤ 按序解析为 `reference_images`，prose 里「图片N」↔ content 第 N 张图 ↔ references[N-1]，三者锁步，绝不会错位。草图板永远排第 1（构图主引导）。

## 七、跨集复用机制（0 抽卡的核心）

```
bible.json(规划: 每角色富 sheet_spec, 跨集一致)
     │
     ▼ ③ 按 ref_token 生成
asset_registry.json(已生成: assets/characters/苏小七.png · used_by:[第1集,第2集…])
     │  同一张图、同一路径 → 跨集复用,不重生成
     ▼ ⑤ 按 ref_path 登记
moyu 素材库(苏小七.png → asset://… · 各集共用一个 moyu 素材 id)
```
- **库资产**（人物多面板表/场景板/道具）跨集是**同一个文件路径** → registry 命中复用 → 一致性天然保证、额度省。
- **色卡 / 草图板**是逐段生成物 → 进 `分段/asset_registry.json` + 绑定，**不进 bible**（bible 只是规划层）。

**两层模型**：`bible` = 规划层（应该长什么样）；`asset_registry` = 已生成层（实际出了哪张图）；`ref_token` 连接两层。

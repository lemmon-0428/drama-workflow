# 短剧「剧本 → 资产」流水线设计

> **⚠ 流程已修订（2026-06）。** 最新流程是 6 阶段：
> **①拆解 → ②设定bible → ③分镜头(可读MD表,4–15s分组) → ④镜头提示词(每组视频提示词+主体/场景/空间站位) → ⑤4b资产(读提示词→生成素材并产出绑定JSON,记path) → ⑥SD2请求(读⑤的JSON拼参数)**。
> 关键改动：**分镜头改为产可读 Markdown 表（不再产结构化 JSON）**；新增 **④镜头提示词** 阶段（在资产之前）；**结构化的资产绑定 JSON 由 ⑤4b 产出**（因为只有它知道素材 path）。
> 已实现：①②③④（各 skill 的 SKILL.md 为准）。待做：⑤把现有 `drama-asset-gen` 重指为"读镜头提示词→出绑定JSON+素材"、⑥SD2。
> 下方 §3.2 的分镜头 JSON schema、§4 的 ③④ 旧描述已被各 skill 的 SKILL.md 取代，仅作历史参考。

把原来的单体 skill 拆成按阶段串联的 skill。本文是它们之间的**契约**：目录结构、ID 约定、各 skill 的职责/输入/输出/触发，以及关键文件的数据格式。

---

## 0. 核心原则

skill 之间**没有共享记忆，只有共享文件系统**。每个 skill 读上一阶段写的文件、写自己阶段的文件。因此：

1. **目录结构 = skill 之间的 API**（见 §1）。
2. **一套统一 ID 把四个阶段串起来**（见 §2）：人物/场景在 bible 里定 id，分镜头按 id 引用，资产按 id 出图与复用。
3. 每个文件都有**唯一归属 skill**（谁产出、谁只读），避免互相覆盖。

## 1. 目录契约（每部剧一棵树）

```
docs/scripts/<剧名>/
├── 00_剧集总览.txt                      [①] 梗概 + 创作设定 + 分集目录
├── bible/                               [②] 全剧设计唯一事实来源
│   ├── 世界观.md                          世界观 / 时代 / 规则 / 基调
│   ├── 人物背景.md                        每角色：背景·性格·关系·弧光 + 造型设计 + 五官锚 + look 规划
│   ├── 场景设定.md                        每场景：环境·氛围 + look 清单（打光/状态变体）
│   └── bible.json                         ②的机器可读索引（角色/场景/look/画风），供 ③④ 消费
├── <第N集_集名>/
│   ├── <剧名>_<第N集_集名>.txt            [①] 本集剧本
│   ├── 分镜头.json                        [③] 本集镜头表（机器，唯一事实来源）
│   ├── 分镜头.md                          [③] 本集镜头表（人读，派生，可选）
│   └── 资产清单.md                        [④] 本集用到/新增的资产（人读）
└── assets/                              [④] 全剧共享资产库
    ├── characters/   <char_id>.png · <char_id>__<look>.png
    ├── scenes/       <scene_id>.png · <scene_id>__<look>.png
    ├── props/        <prop_id>.png
    ├── shots/<第N集_集名>/<镜号>.png      4b 分镜头站位合成图
    ├── asset_registry.json                库资产台账（机器，唯一事实来源）
    └── 角色形象卡.md                       派生人读视图
```

只读 vs 写入：
- `①` 写 `00_剧集总览.txt` 和各集 `剧本.txt`。
- `②` 只读剧本，写 `bible/`。
- `③` 只读 `剧本.txt` + `bible.json`，写各集 `分镜头.{json,md}`。
- `④` 只读 `bible.json` + `分镜头.json`，写 `assets/`、`资产清单.md`，并回写 `分镜头.json` 里每镜的 `shot_image` 字段（标记站位图已出）。

## 2. 统一 ID 约定

- **char_id / scene_id / prop_id**：英文小写下划线，全剧稳定不变（如 `navigator_k`、`noah_ark_interior_hall`）。在 `②bible` 里确定，③④ 一律引用。
- **look**：短标签，描述同一对象的造型/状态/打光变体（`default` / `dim` / `night` / `bloodied` / `disguise_guard`…）。基础形象的 look 即 base。
- **资产文件名**：base = `<id>.png`；变体 = `<id>__<look>.png`（双下划线分隔）。
- **镜号**：`<集序>-<三位镜序>`，如 `2-001`（第2集第1镜）。站位图存 `assets/shots/<第N集_集名>/2-001.png`。
- **集目录名**：`第N集_集名`（如 `第1集_开篇`），沿用现有约定。

**衔接链**：bible 定 `char_id/scene_id` 和它们的 `look` 规划 → 分镜头每镜用这些 id+look 标注涉及的人物(含站位)和场景 → 资产 ④ 按 id+look 取/出库资产，再把它们当参考图合成该镜站位图。三阶段共用同一套 id。

## 3. 关键数据格式

### 3.1 bible.json（②产出，③④消费）—— 全剧设计 SoT

```json
{
  "drama": "巴别塔",
  "style": "8K 超写实真人电影感（AI真人科幻 / Dune·Interstellar）",
  "logline": "一句话故事",
  "characters": [
    {
      "id": "navigator_k",
      "display_name": "领航员K",
      "identity_anchor": "40-year-old Chinese man, deep-set tired eyes like an extinguished volcano, short cropped black hair flecked with grey, tall lean build   ← 英文·锁五官·所有 look 复用",
      "bio": "诺亚方舟最后的领航员，沉默压抑……（背景/性格/关系/弧光，中文）",
      "looks": [
        {"look": "default", "desc": "炭灰长袍领航装", "outfit_prompt": "wearing a dark charcoal coat-robe…（仅造型部分英文）", "episodes": ["第1集_开篇","第2集_乘客","第3集_抉择"]},
        {"look": "chest_reveal", "desc": "衬衫掀开露机械胸腔+血", "parent": "default", "outfit_prompt": "shirt torn open revealing a mechanical chest cavity, blood-streaked", "episodes": ["第4集_倒塌"]}
      ]
    }
  ],
  "scenes": [
    {
      "id": "noah_ark_interior_hall",
      "display_name": "诺亚方舟内部大厅",
      "desc": "空旷飞船大厅，落地舷窗，东方禅意压抑",
      "looks": [
        {"look": "dim", "desc": "默认幽暗·舷窗冷光", "episodes": ["第1集_开篇","第2集_乘客"]},
        {"look": "night", "desc": "夜·月光唯一光源", "parent": "dim", "episodes": ["第3集_抉择"]},

```

> bible.looks = **规划**（通读全剧得到的"应该有哪些 look 及用在哪几集"）；asset_registry = **已生成**。两者分工：bible 说该有什么，台账记已经做了什么。

### 3.2 分镜头.json（③产出，④4b消费）—— 每集镜头表

```json
{
  "episode": "第2集_乘客",
  "shots": [
    {
      "id": "2-001",
      "景别": "全景", "机位": "平视", "镜头运动": "固定", "时长_秒": 3,
      "画面": "老人从隔间走出，对着高台上的K和盘坐的机器人开口",
      "台词": "You know, the apocalypse is God's test for us…",
      "scene": {"id": "noah_ark_interior_hall", "look": "dim"},
      "characters": [
        {"id": "navigator_k", "look": "default", "站位": "画面右·坐在高台", "动作": "凝视舷窗外"},
        {"id": "mechanical_monk_robot", "look": "default", "站位": "画面右下·盘坐"},
        {"id": "old_man", "look": "default", "站位": "画面左·从隔间走出", "动作": "伸手布道"}
      ],
      "构图备注": "三分法，老人入画引导视线向右",
      "shot_image": null        // ④4b 出图后回写路径 + 状态
    }
  ]
}
```

### 3.3 asset_registry.json（④产出）—— 库资产台账

沿用现有扁平 looks 模型：每张库资产一条，字段 `name / category / char_id / look / parent / identity_anchor / display_name / design / path / size / provider / mode / status / first_episode / used_by / prompt`。详见当前 `drama-asset-gen` skill。**站位图(shots)不进这个台账**，其状态回写到 `分镜头.json` 的 `shot_image`。

## 4. 四个 skill 规格

### ① drama-script-split — 剧本拆解
- **触发 description**：把整本/多集合一的短剧剧本（Word/PDF/TXT）按"集或幕"拆成单集文件，建立 `docs/scripts/<剧名>/` 目录与剧集总览。当用户给的是一整本剧本、要"拆分单集 / 分集 / 按集切开 / split script into episodes"时触发。**只做结构切分，不做创作**。
- **输入**：整本剧本文件（docx/pdf/txt）
- **输出**：`00_剧集总览.txt` + 各 `第N集_集名/<剧名>_<第N集_集名>.txt`
- **职责**：识别分集/分幕标记（显式或推断，含无显式首幕的情况）、时间码、front matter（梗概/风格）；切分；中英对照原样保留；做"非空段落无丢失"校验。
- 现状：目前是手写 python（如 split_babel.py）干的，formalize 成 skill + 内置脚本。

### ② drama-bible — 剧本设定 / 人物背景
- **触发 description**：读剧本，产出"设定集 bible"——世界观、人物背景小传（性格/关系/弧光）+ 造型设计 + 五官锚 + 形象 look 规划、场景设定 + 全剧画风，写入 `bible/` 与 `bible.json`，作为全剧设计唯一事实来源。当用户要"生成人物背景/人物小传/世界观/设定集/角色设定/character bible/角色造型设计"时触发。
- **输入**：各集 `剧本.txt`（全剧或指定集）
- **输出**：`bible/世界观.md`、`人物背景.md`、`场景设定.md`、`bible.json`
- **职责**：抽取并扩写角色背景；像造型师一样设计具体造型（单品级）；提炼**五官锚**（英文，锁脸，变体逐字复用）；通读全剧规划每个角色/场景的 **look 时间线**（贴合剧情变化：换装/受伤/伪装/反转/打光）；定**全剧画风 style**。
- 边界：造型设计、五官锚、画风都归这里（不留在资产 skill），保证设计只有一处来源。

### ③ drama-storyboard — 分镜头
- **触发 description**：读单集剧本 + bible，生成分镜头表——逐镜的镜号/景别/机位/时长/画面/台词/镜头运动，并为每镜标注涉及的人物（id + look + 站位调度）和场景（id + look），写入 `<集>/分镜头.json`。当用户要"生成分镜头/分镜脚本/storyboard/镜头表/拉片"时触发。
- **输入**：`<集>/剧本.txt` + `bible.json`
- **输出**：`<集>/分镜头.json`（机器）+ `分镜头.md`（人读，可选派生）
- **职责**：按叙事节奏切镜；为每镜定景别/机位/构图/运动；用 bible 的 id 标注涉及人物（含**站位/调度/动作**）和场景（含 look）。这是 ④ 站位资产的**需求来源**。

### ④ drama-asset-gen — 资产生成（当前 skill 瘦身 + 扩展）
- **触发 description**：读 bible + 分镜头，调用多渠道 gpt-image-2 生成两类资产：①**库资产**（人物定妆照 / 场景空镜 / 形象变体，跨集复用、台账追踪）；②**分镜头站位合成图**（把场景板 + 相关人物参考图用图生图合成每一镜的站位画面）。当用户要"生成人物/场景资产、角色定妆照、场景图、角色变体/换装图、分镜头站位图/合成镜头画面"时触发。
- **输入**：`bible.json`（设计）+ `分镜头.json`（需求/站位）+ `assets/`（已有库）
- **输出**：`assets/characters|scenes|props/*.png`、`assets/shots/<集>/*.png`、`asset_registry.json`、`角色形象卡.md`、`<集>/资产清单.md`；回写 `分镜头.json` 的 `shot_image`
- **职责**：
  - **4a 库资产**：按 bible 设计 + 分镜头实际需求，去重生成/复用；新 base 出定妆照/空镜；变体用五官锚 + 图生图（`ref`=parent 图）锁一致性；维护台账。
  - **4b 站位合成**：对每个镜头，取 `scene.id+look` 的场景板与 `characters[].id+look` 的人物图，一起作为多张参考图（packy/moyu 的 images/edits 最多 16 张）+ 站位/景别/构图 prompt → 合成该镜画面。**4a 必须先于 4b**（库资产是站位图的参考）。
  - 三种生成模式仍在：B 增量（默认）/ 只读规划 / A 全量（显式 opt-in）。
  - 多渠道 micu → packy → moyu 失败回退，生成/编辑双模式（已实现于 `scripts/generate_images.py`）。

## 5. 边界决策记录

1. **造型设计 / 五官锚 / 画风 归 ②bible**，不留在 ④。设计只有一处来源，分镜头与资产都消费它。
2. **4a 库资产先于 4b 站位图**：库资产是站位合成的参考图。
3. **不拆成 5 个 skill**：4a/4b 共用同一生图引擎与资产库，合在 ④ 内做两个模式；将来 4b 复杂了再独立。
4. **触发用阶段名锚定、避免互抢**：拆解=切分文件 / 设定=世界观人物背景 / 分镜头=镜头表 / 资产=出图；主要靠 `/命令` 显式调用。
5. **bible.looks=规划、registry=已生成**；**站位图状态回写分镜头.json**，不进库资产台账。

## 7. 端到端流程示意

```
整本剧本.docx
   │ ①拆解
   ▼
docs/scripts/<剧名>/<第N集>/剧本.txt  +  00_剧集总览.txt
   │ ②设定（通读全剧）
   ▼
bible/ + bible.json   （世界观·人物背景·造型·五官锚·look规划·画风）
   │ ③分镜头（逐集，引用 bible 的 id）
   ▼
<集>/分镜头.json      （每镜：景别/机位/画面/台词 + 人物id+look+站位 + 场景id+look）
   │ ④资产
   ├─ 4a 库资产：characters/ scenes/ props/（定妆照·空镜·变体，台账追踪）
   ▼
   └─ 4b 站位合成：shots/<集>/<镜号>.png（场景板+人物参考图→每镜站位画面）
```

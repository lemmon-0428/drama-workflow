# 资产锚定方案（ref_token + SD2 请求拼装）

> 人物/场景/道具/色卡/草图板全部 ref_token 锚定，⑤ 据此把四件套拼成 Seedance 请求。

## ref_token 类型
| 类型 | token | 指向 | 资产层 |
|---|---|---|---|
| 人物 | `@[char:<id>\|look:<look>]` | 多面板角色参考表 | assets/characters/ |
| 场景 | `@[scene:<id>\|look:<look>]` | 场景板 | assets/scenes/ |
| 道具 | `@[prop:<id>]` | 道具图 | assets/props/ |
| **色卡(新)** | `@[palette:<id>]` | 13色色卡(按场景复用) | <集>/分段/scenes/ |
| **草图板(新)** | `@[board:<seg_id>]` | 草图分镜板(每段一张) | <集>/分段/scenes/ |

## 两处用到锚定
1. **生成草图板时**（板的一致性）：板里的 HUD 用 `@[prop:system_hud]` 资产做 `ref` 走编辑模式生成 → 板里 HUD 是中文"步数/余额"。（否则会跑成英文。）
2. **拼 SD2 请求时**（视频的一致性）：每段**锚定清单**=有序参考图集，连同段 prose 一起送 Seedance；每个 `@token` → 注册表查 path → OSS → moyu 素材库 `asset://id` → `reference_image`。**草图板永远第1**（构图主引导）。

## SD2 请求怎么拼（⑤ 逻辑）
```
对每段：
  text   = 段 prose 全文（场景1_段提示词.md#SEG-1A）
  images = 锚定清单按序 → 资产绑定.json 查 path → OSS 上传签名URL → moyu CreateAsset → asset://id
  payload.metadata.content = [{type:text,text}, {type:image_url,image_url:asset://id,role:reference_image} × N]
  duration=12, resolution=720p, ratio=16:9
```
注：moyu first_frame 与 reference_image 互斥 → 全走 reference_image，首帧意图写进 prose。**本环节默认只产请求/预览，真正提交需单独确认。**
